# 화면 명세

각 화면의 구성 요소, 상태, API 연동, 엣지 케이스를 정의한다.

---

## `/` — 랜딩

### 구성

```text
┌──────────────────────────────────────────┐
│  [로고]                          소개     │  헤더
├──────────────────────────────────────────┤
│                                          │
│   목표만 알려주세요.                       │  히어로
│   공고는 저희가 모아옵니다.                 │
│                                          │
│   기업 규모와 직군을 고르면, AI가 5번       │
│   물어보고 조건을 정리해 여러 채용 사이트    │
│   에서 공고를 모아 드려요.                  │
│                                          │
│   [ 시작하기 → ]                          │
│                                          │
│   ┌── 이어서 하기 ───────────────┐        │  세션 있을 때만
│   │ 진행 중인 대화가 있어요 (3/5) │        │
│   │              [이어서 하기 →] │        │
│   └──────────────────────────────┘        │
├──────────────────────────────────────────┤
│  ① 목표 입력  ② AI 대화  ③ 조건 확인      │  3단계 설명
│  ④ 공고 모아보기                          │
├──────────────────────────────────────────┤
│  공고 출처: 고용24 · 사람인 · 기업 채용 페이지│  푸터
│  회원가입 없이 바로 시작할 수 있어요.        │
└──────────────────────────────────────────┘
```

### 상태

| 상태 | 조건 | 표현 |
| --- | --- | --- |
| 기본 | `localStorage`에 세션 없음 | "시작하기"만 |
| 이어서 하기 | 세션 있고 `GET /sessions/:id` 성공 | 진행률 배너 + 복귀 링크 |
| 만료된 세션 | 세션 있으나 404 | `localStorage` 정리 후 기본 상태 |

### 렌더링

Server Component. "이어서 하기" 배너만 Client (localStorage 접근 필요). `Suspense`로 감싼다.

## `/start` — 목표 입력

### 구성

```text
┌──────────────────────────────────────────┐
│  ●───○───○───○   ① 목표 입력              │  진행 표시
├──────────────────────────────────────────┤
│  어떤 곳을 목표로 하고 계세요?              │
│                                          │
│  기업 규모 *                     복수 선택 │
│  [대기업] [중견기업] [중소기업]            │
│  [스타트업] [공공·공기업] [외국계]         │
│                                          │
│  직군 *                                   │
│  [개발] [기획/PM] [디자인] [마케팅]        │
│  [영업] [데이터] [경영지원] [생산]         │
│                                          │
│  세부 직무                    복수 선택    │  ← 직군 선택 시 노출
│  [백엔드] [프론트엔드] [모바일] ...        │
│                                          │
│  경력 구분 *                              │
│  [신입] [인턴] [경력 3년 이하]             │
│                                          │
│  희망 지역                    복수 선택    │
│  [서울] [경기] [인천] ... [재택·원격]      │
│                                          │
│  고용 형태                    복수 선택    │
│  [정규직] [계약직] [인턴] [체험형]         │
│                                          │
│  언제부터 일하고 싶으세요?                  │
│  [즉시] [3개월 이내] [6개월 이내] [유동적]  │
│                                          │
│              [ AI와 대화 시작하기 → ]      │
└──────────────────────────────────────────┘
```

### 규칙

- 필수는 `companySizes`(1개 이상), `jobFamily`, `experienceLevel` 3개.
- `roles`는 `jobFamily`를 고르면 그 하위 역할만 노출한다. 미선택 시 전체로 간주.
- 선택지는 `GET /taxonomy`에서 온다. 하드코딩하지 않는다.
- 제출 버튼은 필수 항목이 채워질 때까지 `disabled` + `aria-disabled`.

### API

```text
GET  /taxonomy                → 선택지 (Server Component에서 fetch, 1시간 캐시)
POST /sessions { goalInput }  → 201 { sessionId, turn, remainingTurns }
                              → router.push(`/discovery/${sessionId}`)
```

### 엣지 케이스

| 상황 | 처리 |
| --- | --- |
| `POST /sessions` 실패 (5xx) | 인라인 에러 + 재시도 버튼. 폼 값 유지 |
| 첫 질문이 `fallback: true` | 구분 없이 진행 |
| 이미 진행 중인 세션 존재 | "새로 시작하면 진행 중인 대화가 사라집니다" 확인 |

## `/discovery/:sessionId` — AI 대화

### 구성

```text
┌──────────────────────────────────────────┐
│  ○───●───○───○   ② AI 대화     3/5 턴     │
├──────────────────────────────────────────┤
│                                          │
│  🤖 개발 직군 안에서도 결이 꽤 다른데요,    │  질문 (aria-live)
│     어떤 쪽에 가장 끌리세요?               │
│                                          │
│     [서버·API] [데이터 파이프라인]         │  선택지 칩
│     [프론트엔드] [인프라·DevOps]           │
│     [아직 모르겠어요]                      │
│                                          │
│     ┌────────────────────────────┐        │  자유 입력
│     │ 직접 입력하기...      [→]  │        │
│     └────────────────────────────┘        │
│                                          │
│  ─────────── 이전 대화 ───────────         │
│                                          │
│  🤖 (턴 2) 지금 다룰 수 있거나...          │  접힌 히스토리
│  🙂 Java랑 Spring 공부하고 있어요  [수정]  │
│                                          │
│  🤖 (턴 1) 개발 직군 안에서도...           │
│  🙂 서버·API                      [수정]  │
│                                          │
└──────────────────────────────────────────┘
```

### 상태 머신

```text
idle ──(선택/입력)──▶ submitting ──(200 interviewing)──▶ idle (다음 턴)
                          │
                          ├──(200 criteria_ready)──▶ /discovery/:id/criteria
                          ├──(422 TURN_BUDGET)─────▶ /discovery/:id/criteria
                          └──(5xx)─────────────────▶ error (재시도)
```

### 로딩 표현

`submitting` 동안:

```text
🤖 ● ● ●          0 ~ 3초   타이핑 인디케이터
🤖 ● ● ● 조금만 더요  3초 ~   문구 추가
                  30초~     타임아웃 → 폴백 질문 또는 에러
```

선택지와 입력은 `submitting` 동안 비활성화한다. 중복 제출을 막는다.

### 답변 수정

이전 턴의 `[수정]`을 누르면:
1. 확인 다이얼로그 — "이후 대화가 다시 진행됩니다"
2. 해당 턴부터 재시작 (백엔드는 세션 롤백 API가 없으므로 MVP에서는 **새 세션 생성 + 이전 답변 재제출**로 구현)

> MVP 범위 결정: 턴 롤백 API는 백엔드에 없다. 프론트에서 "새 세션 + 재생"으로 처리하면 LLM 호출이 중복된다. **MVP에서는 `[수정]`을 마지막 턴에만 노출**하고, 그 외에는 조건 확인 화면에서 고치도록 안내한다.

### API

```text
POST /sessions/:id/turns { answer, choiceValue }
  200 { status: "interviewing",   turn, remainingTurns }
  200 { status: "criteria_ready", criteria, estimatedCount }
  409 SESSION_STATE_INVALID  → 세션 status로 올바른 화면 재라우팅
  422 TURN_BUDGET_EXCEEDED   → /criteria로 이동
```

## `/discovery/:sessionId/criteria` — 조건 확인

### 구성

```text
┌──────────────────────────────────────────┐
│  ○───○───●───○   ③ 조건 확인              │
├──────────────────────────────────────────┤
│  이 조건으로 공고를 모아올게요.             │
│  예상 143건 · 마음에 안 드는 항목은 고쳐주세요│
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ 기업 규모          폼에서 입력 [수정]│  │
│  │ 중견기업 · 대기업                   │  │
│  ├────────────────────────────────────┤  │
│  │ 직군 · 세부 직무    1번째 답변 [수정]│  │
│  │ 개발 › 백엔드                       │  │
│  ├────────────────────────────────────┤  │
│  │ 기술 스택          2번째 답변 [수정]│  │
│  │ Java · Spring · MySQL              │  │
│  ├────────────────────────────────────┤  │
│  │ 포함 키워드        3번째 답변 [수정]│  │
│  │ 금융 · B2B                          │  │
│  ├────────────────────────────────────┤  │
│  │ 제외 조건          4번째 답변 [수정]│  │
│  │ 교대근무 · 파견                     │  │
│  ├────────────────────────────────────┤  │
│  │ 정렬 우선순위          기본값 [수정]│  │
│  │ 기술 40% · 직무 30% · 지역 20% ...  │  │
│  └────────────────────────────────────┘  │
│                                          │
│  ⓘ '정렬 우선순위'는 대화에서 정해지지 않아 │  unfilledSlots 안내
│     기본값을 사용했어요.                   │
│                                          │
│         [ 이 조건으로 공고 모으기 → ]      │
└──────────────────────────────────────────┘
```

### 출처 표시

`criteria.sources[field].origin`을 사람이 읽는 라벨로 변환한다.

| origin | 라벨 |
| --- | --- |
| `form` | "폼에서 입력" |
| `turn` (turnIndex: n) | "n번째 답변" |
| `default` | "기본값" |
| `manual` | "직접 수정함" |

### 수정 인터랙션

`[수정]`을 누르면 해당 행이 인라인 편집 모드로 바뀐다. 필드 타입별 컨트롤:

| 필드 | 컨트롤 |
| --- | --- |
| `companySizes` `regions` `employmentTypes` `roles` | 다중 선택 칩 |
| `jobFamily` `experienceLevel` | 단일 선택 칩 |
| `techStack` `keywords` `excludeKeywords` | 태그 입력 (최대 개수/글자수 제한 표시) |
| `salaryMin` | 숫자 입력 |
| `weights` | 4개 슬라이더, 합 100 자동 정규화 |

저장하면 `PATCH`로 새 버전이 생기고 `estimatedCount`가 갱신된다. 이때 예상 건수 변화를 애니메이션으로 보여준다 (143 → 87).

### API

```text
GET   /sessions/:id/criteria           → 조건 + 출처 + estimatedCount
PATCH /sessions/:id/criteria { ... }   → 새 버전 + 갱신된 estimatedCount
POST  /sessions/:id/criteria/confirm   → 202 { feedId } → /feed/:id
```

## `/feed/:sessionId` — 공고 피드

### 수집 중

```text
┌──────────────────────────────────────────┐
│  ○───○───○───●   ④ 공고 모으는 중          │
├──────────────────────────────────────────┤
│  여러 채용 사이트에서 공고를 모으고 있어요.  │
│                                          │
│  ✓ 고용24            88건                │  role="status"
│  ✓ 사람인            61건                │
│  ⟳ 기업 채용 페이지   수집 중...          │
│  · HTML 크롤러       사용 안 함           │
│                                          │
│  ░░░░░░░░░░░░░░░░  스켈레톤 카드 3장      │
└──────────────────────────────────────────┘
```

2초 간격 폴링. 60초를 넘기면 폴링을 멈추고 "예상보다 오래 걸리네요" + 수동 새로고침 버튼.

### 완료

```text
┌──────────────────────────────────────────┐
│  143건  ·  조건 수정                      │
│  [매칭순 ▾] [80점 이상 ▾]                 │  정렬·필터
├──────────────────────────────────────────┤
│  ┌────────────────────────────────────┐  │
│  │ 정규직 · 중견기업 · 서울    D-6     │  │
│  │ 백엔드 개발자 (신입)               │  │
│  │ 토스페이먼츠                        │  │
│  │                                    │  │
│  │ 92점                               │  │
│  │  ✓ 기술 스택 3개 일치               │  │
│  │    (Java, Spring, MySQL)           │  │
│  │  ✓ 희망 지역 일치 (서울 강남)        │  │
│  │  ✓ 신입 채용 명시                   │  │
│  │  △ 제외 조건 '교대근무' 관련 언급 없음│  │
│  │                                    │  │
│  │ 사람인 · 2일 전 · 고용24에도 게시    │  │
│  └────────────────────────────────────┘  │
│  ... (무한 스크롤)                        │
└──────────────────────────────────────────┘
```

### 카드 규칙

- **점수 옆에는 항상 `reasons`가 붙는다.** `reasons`가 빈 배열이면 그 카드는 렌더하지 않고 에러로 보고한다 (API 계약 위반).
- `reasons`는 최대 4개까지 보여주고, 더 있으면 "+n개 더".
- `companySizeInferred`가 `true`면 규모 옆에 "추정" 배지.
- `alsoFoundOn`이 있으면 "고용24에도 게시" 표기.
- `closesAt`이 3일 이내면 D-day 배지를 강조색으로.
- `isRolling`이면 D-day 대신 "상시채용".

### 정렬·필터

| 컨트롤 | 옵션 | 구현 |
| --- | --- | --- |
| 정렬 | 매칭순 / 최신순 / 마감임박순 | `?sort=score\|recent\|deadline` — 서버 재조회 |
| 최소 점수 | 전체 / 60+ / 80+ | `?minScore=` — 서버 재조회 |

클라이언트 필터링을 하지 않는다. 페이지네이션과 어긋난다.

### 실패

```text
┌──────────────────────────────────────────┐
│  😔 공고를 가져오지 못했어요                │
│                                          │
│  채용 사이트 응답이 원활하지 않습니다.       │
│  잠시 후 다시 시도해 주세요.                │
│                                          │
│  [ 다시 시도 ]    [ 조건 수정하기 ]        │
└──────────────────────────────────────────┘
```

`retryable: false`면 "다시 시도"를 감춘다.

### 결과 0건

```text
조건에 맞는 공고를 찾지 못했어요.

가장 큰 제약은 '제외 조건 3개'로 보입니다.
[ 조건 완화하고 다시 찾기 ]
```

어떤 조건이 결과를 0으로 만들었는지는 백엔드가 `sourceSummary`와 함께 힌트를 주지 않으므로, MVP에서는 **조건 개수 기준 휴리스틱**으로 안내한다 (excludeKeywords > regions 1개 > techStack 5개 초과 순).

### API

```text
GET  /sessions/:id/feed?cursor&limit&sort&minScore
POST /sessions/:id/feed/refresh   → 202 (5분 1회 제한, 429 처리)
```

## `/about` — 서비스 소개

공고 출처와 수집 정책을 공개한다. 사용자가 "이 공고 어디서 가져온 거지"를 확인할 수 있어야 한다.

포함 내용:
- 무엇을 하는 서비스인가
- 어느 소스에서 공고를 가져오는가 (`GET /ingestion/sources`의 공개 가능한 부분)
