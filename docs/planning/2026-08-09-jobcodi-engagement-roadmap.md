# JobCodi 참여·지원 전환 로드맵

> 2026-08-09 · 제품 기획 로드맵 · 구현 순서는 아래 순서를 따른다.

## 제품 목표

JobCodi를 `맞춤 공고 발견`만 하는 서비스에서 **발견 → 판단 → 지원 실행 → 재방문**을 돕는 계정 기반 채용 탐색 서비스로 확장한다. 공고 원문, 이력서 파일, 외부 사이트 로그인 정보는 보관하거나 자동 처리하지 않는다.

## 현재 기반

- 계정당 활성 조건 프로필 1개와 매일 06:00 KST 갱신
- 고용24·사람인·잡코리아·자소설닷컴 선택형 수집
- 공고별 관심 저장/제외, 서버 기반 `saved` Feed 필터
- 원문 공고 사이트로만 이동하는 상세/CTA

## 우선순위 기준

1. 사용자가 이미 한 행동(관심 저장)을 실제 지원으로 연결하는가
2. 개인정보·외부 사이트 약관 위험 없이 제공 가능한가
3. 기존 활성 프로필·Feed·preference 도메인을 재사용하는가
4. 실수집/운영 API key가 없어도 기능 UX와 회귀 테스트를 검증할 수 있는가

## 1번: 지원 관리 보드의 제품 경계

- **포함:** 사용자의 지원 상태, 예정일, 실제 지원일, 짧은 메모, 원문 공고 이동, 마감 현황
- **제외:** 이력서 업로드·저장, 자동 지원, 외부 채용 사이트 인증, 지원 결과 자동 수집, 알림 발송
- **상태:** `reviewing`(검토 중) → `planned`(지원 예정) → `applied`(지원 완료) / `closed`(종료)
- **소유권:** 사용자 + 공고 복합 유일. 다른 사용자는 서로의 지원 항목을 볼 수 없다.
- **관심과의 관계:** 보드에 추가하면 해당 공고를 `saved`로 보장한다. 이후 관심 해제는 지원 보드 항목을 삭제하지 않는다.
