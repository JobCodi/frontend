# 매칭 근거 고도화 설계

## 목표

공고 상세에서 서버가 이미 계산한 `score`, `scoreBreakdown`, `reasons`를 재계산하지 않고, 사용자가 지원 판단에 바로 쓸 수 있도록 **강점·확인할 점·조건 차이**와 항목별 기여도를 정리한다.

## 범위

- 상세 화면에 `매칭 해석` 카드를 추가한다.
- `scoreBreakdown`의 `roleMatch`, `techMatch`, `regionMatch`, `freshness`, `penalty`를 서버 값 그대로 표시한다.
- `reasons`는 kind 기준으로 분류한다.
  - `match` → 맞는 점
  - `caution` → 확인할 점
  - `gap` → 조건 차이
- 빈 그룹은 표시하지 않는다.
- 기존 `왜 추천했나요` 원문 근거 목록은 유지한다.

## 비범위

- 클라이언트 점수 재계산·재정렬
- 공고 본문 수집·저장·재노출
- 사용자의 해석 피드백 저장 또는 조건 자동 변경
- Backend API 또는 scoring formula 변경

## 접근성

- 색 이외에 그룹 제목과 아이콘으로 의미를 전달한다.
- 기여도는 `dl`의 텍스트 값으로 표현한다.
- reasons가 비어 있으면 기존 계약 위반 처리 흐름을 유지한다.

## 수용 기준

1. 상세 화면에 서버 점수와 항목별 기여도가 보인다.
2. match/caution/gap 이유가 각각 해당 그룹으로 표시된다.
3. 이유가 없는 그룹은 렌더하지 않는다.
4. 기술·직무·지역·최신성의 label은 고정 매핑이며 값은 서버 scoreBreakdown이다.
5. 실제 로그인 Feed 상세에서 렌더되고 원문 CTA는 회귀하지 않는다.
