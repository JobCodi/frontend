# 마감 임박 인앱 리마인더 설계

> 로드맵 2번. 지원 관리 보드 다음의 재방문·행동 촉진 slice.

## 문제와 목표

지원 예정 또는 검토 중인 공고는 마감일이 지나면 사용자가 행동할 기회를 잃는다. 첫 버전은 외부 발송 없이, 로그인한 사용자가 앱을 열었을 때 **D-3 이내인 진행 중 지원 공고를 즉시 발견**하게 한다.

## MVP 범위

- 사용자 소유 `reviewing`, `planned` 지원 항목만 조회한다.
- 마감 시각이 지금부터 **3일 이내**이며 아직 지나지 않은 공고만 반환한다.
- 정렬: 마감일 오름차순, 동률은 지원 항목 생성일 내림차순.
- App header의 벨 버튼에 읽지 않은 수를 배지로 표시한다.
- 벨을 누르면 최대 5개 리마인더와 `/applications` 이동 CTA를 보여준다.
- 지원 보드 상단에는 같은 수를 `마감 임박` 지표로 유지한다.

## 의도적으로 제외

- 이메일, Discord, 푸시 발송과 발송 이력
- D-7/D-1 개별 알림 설정 및 읽음 영속화
- `applied`, `closed`, 마감 완료, 상시채용 공고
- 공고 마감일 추정·변경 감지

이들은 배치 전달·중복 방지·수신 동의가 필요한 후속 slice다. 이 MVP는 데이터 영속화를 추가하지 않아도 결정적이고 안전하게 검증된다.

## API 계약

```text
GET /api/v1/applications/reminders
Authorization: Bearer <user token>
```

200 응답:

```ts
{
  reminders: Array<{
    id: string; // application id
    status: "reviewing" | "planned";
    closesAt: string;
    job: { id: string; title: string; companyName: string; url: string };
  }>;
}
```

A/E/X:

| 경우 | 결과 |
| --- | --- |
| A: 본인 진행 중 항목이 D-3 이내 | 마감일 순으로 포함 |
| E: D-3 초과·마감 완료·상시·지원 완료/종료 | 포함하지 않음 |
| X: 인증 없음/잘못된 token | 기존 user auth 규약대로 401 |

## 사용자 경험

1. 로그인한 사용자가 어떤 flow 화면을 열면 header가 리마인더를 조회한다.
2. D-3 이내 공고가 있으면 벨 아이콘에 개수를 표시한다.
3. 사용자가 벨을 누르면 회사·직무·D-day가 보이고, 선택하면 지원 관리 보드로 이동한다.
4. 리마인더가 없으면 배지를 숨기고 패널에 `마감 임박 공고가 없어요`를 보여준다.

## 접근성·안전

- 버튼에는 `마감 임박 알림` aria-label과 항목 수를 제공한다.
- 팝오버는 semantic dialog가 아니라 간단한 지역/목록으로 구현하고 링크는 키보드 포커스 가능해야 한다.
- API는 항상 userId로 scope하며 공고 원문 본문이나 민감한 지원 메모를 내보내지 않는다.
