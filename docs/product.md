# 제품 개요 (프론트엔드 관점)

> 정본 PRD는 backend 레포의 [`docs/product/prd.md`](https://github.com/JobCodi/backend/blob/main/docs/product/prd.md)에 있다. 이 문서는 프론트엔드가 책임지는 범위만 다룬다.

## 1. 한 줄 정의

취준생이 목표하는 기업 규모와 직군을 입력하면, AI가 대화로 5턴 안에 검색 조건을 정교화하고, 서버가 여러 채용 소스에서 수집한 공고를 모아 보여주는 서비스.

## 2. 프론트엔드가 책임지는 것

```text
① 목표 입력    폼 UX, taxonomy 기반 선택지, 검증
② AI 대화      턴 진행, 선택지 칩, 자유 입력, 로딩 상태, 남은 턴 표시
③ 조건 확인    확정 조건 시각화, 출처 표시, 인라인 수정
④ 공고 피드    수집 진행 표시(폴링), 목록, 매칭 근거, 정렬/필터, 상세
```

## 3. 책임지지 않는 것

- **점수 계산.** 서버가 계산한 `score`와 `reasons`를 그대로 렌더한다. 클라이언트에서 재계산하지 않는다.
- **LLM 호출.** 프론트는 AI 프로바이더 키를 갖지 않는다. 대화는 전부 백엔드 API를 경유한다.
- **공고 본문 표시.** 서버가 본문을 주지 않는다. 상세를 보려면 원문 링크로 이동시킨다.
- **로그인.** MVP에 없다. 세션 ID가 유일한 식별자다.

## 4. UX 원칙

### 4.1 대기 시간을 숨기지 않는다

LLM 응답은 2~5초, 수집은 10~30초 걸린다. 스피너 하나로 때우지 않는다.

| 구간 | 표현 |
| --- | --- |
| LLM 턴 응답 | 타이핑 인디케이터 + "생각하는 중" (3초 후 "조금만 더요" 추가) |
| 수집 진행 | 소스별 진행 체크리스트. "고용24 ✓ · 사람인 진행 중 · ..." |
| 수집 완료 직전 | 스켈레톤 카드 3장 |

### 4.2 점수 옆에는 항상 근거가 있다

숫자만 보여주는 카드를 만들지 않는다. 백엔드가 `reasons`를 필수로 내려주는 이유다.

```text
92점   ✓ 기술 스택 3개 일치 (Java, Spring, MySQL)
       ✓ 희망 지역 일치 (서울 강남)
       △ 제외 조건 '교대근무' 관련 언급 없음 — 확인 필요
```

`kind`별 시각 처리:

| kind | 아이콘 | 색 | 의미 |
| --- | --- | --- | --- |
| `match` | ✓ | success | 조건이 맞음 |
| `caution` | △ | warning | 확인이 필요함 |
| `gap` | ✗ | muted | 조건과 어긋남 |

### 4.3 사용자가 언제든 되돌릴 수 있다

- 대화 중 이전 턴 답변을 수정할 수 있다 (해당 턴 이후는 다시 진행).
- 확정 조건의 모든 필드를 직접 고칠 수 있다.
- 피드에서 "조건 수정" 버튼으로 ③으로 돌아갈 수 있다.

### 4.4 "모르겠어요"가 유효한 답이다

모든 턴의 선택지에 "아직 모르겠어요" 계열 옵션이 있다. 이걸 고르면 그 슬롯은 기본값으로 넘어간다. 다시 묻지 않는다.

### 4.5 대화가 실패해도 막히지 않는다

LLM 호출이 실패하면 `fallback: true`가 붙은 고정 질문이 온다. UI는 이를 구분해 표시하지 않는다 — 사용자에게는 그냥 다음 질문이다. 다만 연속 실패로 대화가 중단되면 "AI 응답이 불안정해 입력하신 정보만으로 조건을 만들었습니다"를 명시한다.

## 5. 화면별 성공 기준

| 화면 | 기준 |
| --- | --- |
| `/start` | 30초 안에 제출 가능. 필수 필드는 2개(`companySizes`, `jobFamily`)뿐 |
| `/discovery` | 턴당 사용자 조작 1회. 자유 입력을 강요하지 않음 |
| `/criteria` | 스크롤 없이 전체 조건이 보임 (모바일 기준 접기 허용) |
| `/feed` | 수집 30초 안에 첫 결과. 카드에서 지원 여부 판단 가능 |

## 6. 반응형

모바일 우선. 주 사용 맥락이 이동 중 탐색이다.

| 브레이크포인트 | 레이아웃 |
| --- | --- |
| `< 768px` | 단일 컬럼. 대화는 전체 화면. 피드는 세로 카드 |
| `768px ~ 1024px` | 대화는 중앙 정렬 640px. 피드 2컬럼 |
| `> 1024px` | 조건 요약 사이드바 + 본문. 피드 2컬럼 + 필터 사이드바 |

## 7. 접근성

- 대화 턴은 `aria-live="polite"` 영역에서 갱신한다. 새 질문이 스크린리더로 읽혀야 한다.
- 선택지 칩은 `role="radio"` / `role="checkbox"`가 붙은 실제 버튼이다. `div` + `onClick`이 아니다.
- 수집 진행 상태는 `role="status"`로 알린다.
- 매칭 근거의 아이콘(✓ △ ✗)은 장식이다. `aria-hidden`을 붙이고 의미는 텍스트가 전달한다.
- 포커스 링을 제거하지 않는다.
- 색만으로 정보를 전달하지 않는다 (match/caution/gap은 아이콘 + 텍스트 병행).
